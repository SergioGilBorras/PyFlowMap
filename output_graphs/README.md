# Consumer diagram results

`output_graphs/` contains **results generated by users analyzing their own
Python sources**, not CI results or benchmark evidence.

Without `--output`, each CLI or MCP analyze invocation creates a
**unique dated directory under the current working directory**:

```text
output_graphs/
  README.md                           # only tracked file in the checkout
  2026-10-14_17-10-00_a1b2c3d4/
    <entry-stem>.mmd                  # Mermaid source (always written)
    <entry-stem>.json                 # graph/provenance (always written)
    <entry-stem>.svg                  # if images/all/svg is requested
    <entry-stem>.png                  # if images/all/png is requested
    <entry-stem>.subdiagrams/         # only for subprocess/hierarchical views
      index.html
      <child-id>.mmd
      <child-id>.json
      <child-id>.svg
      <child-id>.png
```

An explicit `--output path` always takes precedence and is not renamed.
The exact sanitized stem comes from the resolved entry point; the CLI JSON
`files` mapping is authoritative. `inspect` only lists symbols on stdout.

Old consumer runs are **never** deleted by the validation script. Source
files are parsed without import or execution.

For real labels with Codex, users first install `.[labeler-codex]`, log into
Codex, authorize sending code excerpts and opt in to the provider through
`--semantic-provider codex` or the configured
`PYFLOWMAP_DEFAULT_SEMANTIC_PROVIDER=codex`. Unconfigured installations
default to offline analysis; never send users' code to a model silently.
